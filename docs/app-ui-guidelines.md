# App 界面与交互经验

这份笔记记录本次 `localasr` 桌面应用打磨后的约定。后续开发类似本地工具型 app 时，优先按这些原则落地，减少反复确认 UI 细节。

## 总体方向

- 工具型 app 的第一屏应该直接进入核心操作，不做落地页、说明页或大面积装饰。
- 界面尽量紧凑，优先保留高频功能；低频配置放到设置页。
- 主界面只承载主流程：选择文件目录、查看文件状态、勾选任务、开始处理、查看进度。
- 默认路径要符合用户直觉：输入目录默认用户目录；转译文本默认保存在音频同目录。
- 选择过的目录要记住，下次打开沿用。

## 主界面布局

- 标题用简短产品名，例如“音频转文本”；说明文字放在标题后面同一行，不要换行占空间。
- 文件目录区用一个清晰的分组框，例如“打开音频文件目录”。
- 打开、刷新、全选、清空等按钮要小而清楚，避免撑大工具栏。
- 表格必须随窗口缩放自适应，不能用过高的最小高度把外框撑破。
- 表格行高保持紧凑，当前经验值约 `28px`；表格最小高度不要太大，当前经验值约 `120px`。
- 表格头部用浅色、低对比风格，避免深色表头和整体轻量工具风格冲突。
- 如果音频已经有输出文件，在音频行下面用缩进子行展示，如 `└─ 转译文件 xxx.txt`。
- 子行右侧提供“定位”按钮，在系统文件窗口中打开或选中文件；macOS 用 Finder 的 `open -R`。
- 转写完成后立即刷新文件列表，让新生成的文本自动挂在音频下面。

## 设置页

- 首次使用最关键的动作要靠前。模型设置中，“下载默认模型”放在第一行。
- App 启动时检查默认模型是否存在；如果没有，提示用户先下载，并提供“打开模型设置”的入口。
- 设置页按钮文案在中文环境下强制使用中文：`确认`、`取消`，不要依赖 Qt 系统默认翻译。
- 下拉框如果定制了 `QComboBox::drop-down`，必须同时显式配置 `QComboBox::down-arrow`，否则部分平台会丢失倒三角。
- 转译设置不要逐项长列表罗列。按语义分组，并尽量双列排布：
  - 基础：语言、设备、说话人、已有结果、输出格式。
  - 切片与静音：目标片段、边界搜索、重叠保护、静音阈值、静音时长。
- 数字输入控件可隐藏老式上下按钮，减少“土味控件感”。

## 结果输出

- TXT 面向阅读，连续相同说话人的片段要合并成自然段，不要每句都重复 `说话人 N:`。
- JSON/SRT 面向机器和时间轴，可以保留 VAD 细粒度分段。
- 纯标点、空片段不要进入最终 TXT/SRT 输出。
- 说话人识别失败时，第一段失败后应禁用后续说话人识别并降级普通转写，避免长音频反复慢失败。
- 日志窗口要展示用户关心的任务状态，不只展示技术步骤。当前每个音频完成时会显示转写耗时，例如 `完成：test.m4a，转写耗时 4秒`。
- 日志文案优先在 `pipeline` 里产生，GUI 只展示。这样 CLI、未来 MCP 和 Agent 调用也能复用同一套状态信息。

## 模型与依赖

- 发布包不要内置大型模型；模型目录由用户选择，默认缓存目录可自动下载。
- 如果目标是离线开箱即用，优先使用 ONNX 小模型路线，而不是把 PyTorch/FunASR 全量模型塞进包。
- 默认模型下载按钮要明显，下载状态要可见。
- 打包 app 体积异常时，优先检查是否把模型目录、缓存、无关大依赖打入包。
- 本地 GUI 不必默认启动 API 服务；Agent/CLI 能力可以作为独立入口后续补齐。

## 验证习惯

- UI 改动后至少运行：
  - `python -m compileall src tests packaging`
  - `python -m unittest discover -s tests`
  - `localasr-gui --smoke-test`
- PySide6 布局/样式变更后，用 offscreen 模式实际构造窗口，能抓到导入、属性、布局对象运行时问题。
- 涉及打包前不要急着 release；先用 `.venv/bin/localasr-gui` 迭代界面，最后再打包。
